# 3ELiDAR v0.5.2 — Camera, Light & Connection Recovery

هذه النسخة تستمر على Stable Core، لكنها تعيد إظهار أهم مصدر يعتمد عليه ARKit: صورة الكاميرا.

## الأولويات

1. تحديد موقع الجهاز وتسجيل كل Pose أولًا.
2. مسح 2D مع ربط Depth بنفس Frame ID.
3. حفظ الجلسة وفصل الالتقاط.
4. بدء المعالجة محليًا بعد أمر المستخدم فقط.

## واجهة الالتقاط

- Camera Feed حقيقية بكامل الشاشة عبر `ARSCNView`.
- نقاط LiDAR للـFrame الحالية فوق الصورة:
  - أخضر: ثقة مرتفعة.
  - أصفر: ثقة متوسطة.
  - برتقالي: ثقة منخفضة.
  - أحمر: Tracking غير طبيعي.
- التغطية السابقة والمسار في خريطة مصغرة.
- Ambient Light Estimate وتحذير عند الإضاءة الضعيفة.
- زر كشاف: منخفض → متوسط → قوي → إيقاف.

## ثبات البيانات

- Pose تُحفظ قبل Depth والشبكة والواجهة.
- لا يوجد `senderBusy` أو `sendInProgress` داخل Stable Core.
- IMU تستخدم كدليل تشخيصي فقط؛ لا تعدل Transform الخام.
- عند Tracking غير طبيعي أو قفزة غير مدعومة، يبدأ Segment جديد بدل خط كاذب.
- المعالجة لا تدمج Depth مرتبطة بـPose غير طبيعية.
- الملف الخام Append-only.

## Windows

الحالة لا تصبح «يستقبل» بمجرد فتح WebSocket. يلزم وصول:

1. `hello_ack`
2. `session_control_ack`
3. `pose_recorded` أو `scan2d_recorded`

وتعرض الواجهة آخر Frame أكد Windows تسجيلها.

## RoomScan

تم تعديل `RoomScanView.swift` فقط لإضافة زر الكشاف وإطفائه عند الخروج أو دخول الخلفية. لم يتغير ViewModel أو RoomPlan أو منطق الحوائط أو الحفظ أو التصدير.

## اختبار القبول

- اختبر في مكان مضاء أولًا، ثم أطفئ الإضاءة وشغّل الكشاف.
- ضع الجهاز ثابتًا دقيقة كاملة.
- امشِ في خط مستقيم وارجع للبداية.
- راقب Tracking وLight Estimate وفواصل المسار.
- فعّل Windows وتأكد أن الحالة تصبح «يستقبل» وأن رقم Frame المؤكدة يتحرك.
